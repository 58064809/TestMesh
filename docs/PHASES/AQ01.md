# AQ01 — Agent / AI 应用质量底座调研

## 问题定义

第一条真实质量闭环以 TestMesh 当前的 AI 需求分析 Agent 作为被测对象：固定一组有人工结论的中文需求样本，执行候选版本，采集完整 Trace，计算确定性指标与人工/模型评估，比较新旧版本并形成准入结论。

这不是再造一个 Agent Harness，也不是开发通用 Trace/Eval 平台。

## 候选调研

| 候选 | 已提供能力 | 适配判断 |
| --- | --- | --- |
| Arize Phoenix | OpenTelemetry/OpenInference Trace、版本化 Dataset、Experiment、代码与 LLM Evaluator、人工 Annotation、结果比较；可本地或自托管，TypeScript 客户端可运行实验 | **推荐作为 AQ01 唯一候选路径**。能覆盖第一条端到端质量闭环，部署和 TestMesh 现有 TypeScript/PostgreSQL 路径相容；许可为 ELv2，自托管免费且无功能门槛，但不按 Apache/MIT 对外再分发 |
| Langfuse | Trace、Dataset、Experiment、Evaluator、比较和 TypeScript SDK；核心 MIT，可自托管 | 能力成熟，但作为第一版会形成与 Phoenix 平行的平台路径；部分企业 RBAC、审计、保留策略属于商业授权。保留为本次未选候选，不预装 |
| promptfoo | YAML/CLI Eval、丰富断言、Agent trajectory 检查、Red Team、JUnit/JSON 输出和 CI | 适合后续安全与对抗评测，不替代 Trace、Dataset、Experiment 统一底座；AQ01 不并行接入 |
| 自建 Trace/Eval | 自定义表、评分任务、实验页面和比较逻辑 | 明确排除；成熟平台已经覆盖这些通用能力 |

## 推荐单一路径

```text
TestMesh 需求/业务 ID
  → Phoenix Dataset（版本化样本与期望结果）
  → Phoenix Experiment 调用被测 Agent
  → OpenTelemetry + OpenInference Trace
  → 确定性 Evaluator + 人工复核（必要时再增加 LLM Judge）
  → Phoenix 实验比较
  → TestMesh 只记录 dataset / experiment / trace ID 与企业准入决定
```

## 为什么不立即实施

选型还必须通过一个真实样本技术尖峰，验证：

1. 当前 Deep Agents/LangGraph 运行能否完整进入 Phoenix Trace；
2. 中文需求问题样本能否形成版本化 Dataset；
3. TypeScript Experiment 是否能直接执行现有 Agent，而不是复制 Agent 逻辑；
4. 结果能否覆盖缺失/歧义/冲突识别、引用正确率、成本和时延；
5. 本机私有部署、数据删除和导出是否满足企业内使用边界。

任一关键条件失败即停在失败点，重新评审候选；不同时安装 Phoenix、Langfuse 和 promptfoo。

## TestMesh 保留边界

- 被测 Agent / AI 应用 ID、版本、环境与企业质量目标。
- Requirement、Dataset、Experiment、Trace、Evaluation、Artifact 的业务映射。
- 人工审批、风险接受和最终准入结论。

Dataset 存储、Trace Viewer、Experiment Runner、Evaluator 调度和比较页面均复用 Phoenix，不在 TestMesh 重做。

## 真实技术尖峰结果（2026-10-08）

- 样本：16 页中文《AI售后系统产品方案 + PRD文档》，SHA-256 `b3ddde603ab879a3755df173044f9d9f6975d734987fad703dfc0208439795e0`。
- 本机 Phoenix 20.19.0；TypeScript 客户端 7.16.0；OpenTelemetry/OpenInference 复用官方 SDK。
- Phoenix Dataset：`RGF0YXNldDox`；最终通过 Experiment：`RXhwZXJpbWVudDo1`；Trace：`4d102016ce81f4a4a25fa2434201b25d`。
- Trace 共 33 个 Span：1 Agent、20 Chain、4 LLM、8 Tool；可看到 Deep Agents、OpenAI Responses、Skill、来源读取和证据中间件。
- 四项代码评测全部通过：结构与证据、候选问题覆盖、引用覆盖、运行预算。
- 最终通过运行发现 20 个待确认问题（11 缺失、6 歧义、3 冲突），48 条原文引用；108,305 tokens，Agent 77 秒，Docling 首次解析 113.55 秒。
- 同一份真实 PDF 已通过产品 `/api/analyze` 上传入口完成端到端验收并持久化：Analysis `e37d8907-00ee-4f31-a033-6775cccdc154`，状态 `candidate`；识别 12 个待确认问题（6 缺失、3 歧义、3 冲突），关联 43 条经过 Docling 元素校准的原文证据。
- 产品报告已持久化该次 Phoenix Trace `87115e87a7c2160638b8d430ca5482aa`，页面提供直达 Phoenix 的运行轨迹入口；TestMesh 只保存业务映射，不实现 Trace Viewer。
- 人工验收页面提供“只看问题”视图和独立问题清单导出；真实报告可直接聚焦 12 个问题，并显示 6 缺失、3 歧义、3 冲突，不需要在 44 个完整分析条目中逐项查找。
- 初始真实运行暴露并修复：Docling 默认 120 秒同步超时、模型改写原文摘录、模型页码与 Docling 元素页码不一致、追踪器加载顺序导致子 Span 缺失。
- 产品入口验收还发现并修复了单文档摘要中的“优先”字样被误判为多来源优先级声明的问题；来源优先级校验现在只在确实存在多份来源时启用，多来源场景仍保持严格拒绝无证据声明。
- Docling 元素编号成为证据真值，服务端按元素 provenance 回填准确页码与逐字原文；不会为通过验收放宽为模糊引用。
- 解析结果按样本 SHA-256 缓存在忽略版本控制的 `data/aq01-parse-cache`，用于重复实验；Dataset/Experiment/Trace/Eval 均由 Phoenix 保存。
- Phoenix 仅绑定本机；遥测、Agent Assistant、MCP、Web 访问和服务端 Bash 已关闭。

`evaluation/ai-after-sales-prd-rubric.json` 当前状态为 `pending-human-approval`。它只是一份候选验收标准；在用户逐项确认真实问题前，不称为正式金标准，也不据此执行企业准入。

### 产品化进展（2026-10-09）

- TestMesh 已增加唯一的“AI 质量评估”入口，展示被测 Agent/版本/环境、候选 rubric、真实需求文件哈希，以及 Phoenix Dataset、Experiment、Trace 的业务映射。
- 候选配置和人工批准记录保存在 PostgreSQL `testmesh_business.ai_quality_profiles`；批准后冻结当前版本，不覆盖历史证据。
- 批准动作受服务端强制约束：关联真实需求中的待确认问题必须全部形成评审结论；当前完成 5/12，剩余 OQ-005～OQ-011，因此按钮保持禁用。
- Dataset、Experiment、Trace Viewer、Evaluator 与比较页面继续由 Phoenix 提供，TestMesh 没有重复实现。
- 已完成 16 个测试文件、61 条自动测试、生产构建和真实浏览器验收；浏览器控制台无错误或警告。
