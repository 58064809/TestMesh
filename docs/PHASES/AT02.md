# AT02 — UI 自动化

## 目标与边界

AT02 解决 Approved TestCase 到真实浏览器执行与失败证据的闭环。TestMesh 不自研浏览器控制、录制、测试规划、代码生成或失败修复 Agent，只保留项目配置、业务 ID 映射、人工授权、执行入口和结果证据。

2026-10-13 用户明确批准在 AT01 缺少真实公司契约与 URL 的情况下继续 AT02。AT01 平台闭环已通过，但仍不得称为真实售后业务 API 验收。

## 调研与选型

- 单一浏览器测试引擎：`@playwright/test` 1.64.0，Chromium。
- 测试规划、生成和失败修复：Playwright 官方 Test Agents（planner、generator、healer），支持 `npx playwright init-agents --loop=codex`。TestMesh 不再实现 UI Test Agent Loop。
- 执行与证据：Playwright Test JSON Reporter 作为结果源，失败时使用官方 Trace Viewer 可读取的 `trace.zip`；截图由 Playwright 配置管理。
- 官方 healer 可能把持续失败的用例标记为 `fixme()`。TestMesh 将任何 `skipped/fixme` 结果判为未通过，禁止以跳过用例绕过 Approved TestCase 验收。
- 现有 Docker-only 1.62.1 路径已删除。本机没有 Docker，当前唯一执行路径是在用户明确审阅并授权后，以本机 Node 子进程运行目标仓库固定的 Playwright 1.64.0。页面必须直说它会执行仓库代码，不能伪装成隔离运行。
- 目标仓库、API 默认环境和 UI 默认环境统一归入项目配置；执行页只选择 Approved TestCase、已配置环境和仓库内测试文件，不重复维护长期配置。
