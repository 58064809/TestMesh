# BR01 — 业务规则

> **已撤回（2026-10-08）**：该探索把推荐表候选实现成独立业务模块，偏离 Agent / AI 应用质量保障主线。页面、API、存储、运行时与测试已删除；本文只保留调研证据。DMN 未来只有在具体质量场景证明必要时才重新评审。

## 目标

把需求基线中经人工确认的业务规则映射为标准 DMN，并由成熟引擎执行 FEEL、判定表验证和决策计算。TestMesh 只保留规则来源、基线关联、人工审阅、运行入口与证据，不实现规则语言或判定算法。

## 调研与单一选型

- **选定：Apache KIE DMN 10.2.0**。该版本支持 DMN 1.6，提供完整 DMN Runtime、FEEL 和决策表静态分析，采用 Apache-2.0 许可，并要求 Java 21。
- **不选 Camunda 作为本阶段引擎**：`feel-scala` 是成熟 FEEL 组件，但不是完整 DMN 模型执行与验证路径；Camunda 8 平台又超出本阶段所需的业务规则能力。
- **不自建编辑器**：KIE 10.2 已移除 classic DMN editor。本阶段接收标准 DMN XML，避免把低代码建模器、版本管理和协作平台重新做进 TestMesh。
- **不保留备用规则 JSON 或表达式引擎**：KIE 不可用、模型非法、决策失败或超时均原样停止和留证。

## 固定运行时

| 组件 | 固定版本 | 完整性校验 |

| Apache KIE DMN | 10.2.0 | Maven 依赖锁定；可重复构建的 Runner SHA-256 `49beda5f8555be57435d3141fdb2aecdc9a9a0364077c9ce84d74f7a7bd737dd` |

运行 `npm run setup:dmn` 后，工具只写入忽略版本控制的 `data/business-rules-tools`。服务每次运行前校验 Runner 哈希；缺失或不一致立即失败。

## 已实现边界

1. 页面只能选择不可覆盖的 Requirement Baseline，并只能关联其中已接受的 `business_rules` ID。
2. DMN XML、Decision 名称、输入 JSON、审阅人和人工确认均为必填；不把 AI 候选直接当作获批规则。
3. Java 进程不经 shell 启动，并限制 XML/输入/输出大小、超时和最大堆；启用 KIE 标准严格模式与运行时类型检查。
4. KIE 先执行 schema、model 与 decision-table analysis，再执行指定 Decision；验证错误、求值错误、Runner 错误和超时分别记录。
5. PostgreSQL 保存基线、业务规则 ID、DMN、输入、审阅人、引擎版本、退出码、完整结果与日志；历史摘要不加载大字段。
