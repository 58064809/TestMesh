# DI01 — 成熟文档解析能力接入

## 目标

将 PDF、Office、电子表格、图片 OCR、表格识别和版面分析交给成熟组件。TestMesh 只保留上传入口、原文件字节与 SHA-256、来源 ID、原文引用和下游展示，不实现 OCR、表格恢复、阅读顺序或版面算法。

## 选型调研（2026-10-06）

| 候选 | 优点 | 不作为当前唯一主路径的原因 |
| --- | --- | --- |
| Docling / Docling Serve | PDF、DOCX、PPTX、XLSX、图片等统一转换；DoclingDocument 原生包含文本、表格、图片、层级、坐标和 provenance；稳定 v1 HTTP API；MIT；支持离线与 CPU/GPU 部署 | 旧版 DOC/PPT/XLS 依赖额外的 LibreOffice 转换层，因此首轮只开放已真实验收的现代 Office 格式 |
| PaddleOCR PP-StructureV3 | 中文 OCR、表格、公式、阅读顺序能力强；Apache-2.0；支持服务化 | 图像/PDF 解析和 Office `doc2md` 是不同能力入口；默认完整管线资源占用较高；TestMesh 仍需自行统一两套输出与定位 |
| MinerU 4.0 | 中文复杂文档能力强；统一多格式、V1 API、分档质量、稳定页/块定位和本地文档库 | 4.0 于 2026-09 才发布，接口仍处在快速修订期；许可证在 Apache-2.0 基础上增加营收/MAU阈值和在线服务标识义务，企业采用需单独法务判断 |
| Unstructured | Apache-2.0；格式多；成熟的分区、OCR、表格与 ETL API | 高质量 PDF/图片依赖 `hi_res` 及额外模型；统一版面语义与表格能力不如专用文档模型，且会引入较重的 ETL/RAG 能力面 |
| Apache Tika | Apache-2.0；格式覆盖极广；稳定的文本与元数据抽取 | OCR 默认依赖外部 Tesseract，复杂表格和版面恢复不是核心优势，不满足本阶段的统一高质量结构化目标 |

## 决策

采用 **Docling Serve v1** 作为唯一复杂文档解析入口，生产部署固定到经真实验收的明确版本；首轮目标版本为 `docling-serve 1.33.0`。选择依据：

1. 一个服务和一个 DoclingDocument 模型覆盖当前所需格式，避免在 TestMesh 内拼接 PDF、Office、OCR 和表格解析器。
2. provenance 提供页码与元素坐标，能够直接支撑 TestMesh 的原文引用，而不是根据 Markdown 猜位置。
3. MIT 许可、离线运行、CPU/GPU 镜像和稳定 v1 API 更适合企业内网部署。
4. PaddleOCR/MinerU 可作为后续重新选型候选，但不作为隐藏 fallback，也不与 Docling 并行维护。

## 单一路径

`上传原文件 → TestMesh 分配来源 ID/计算哈希 → Docling Serve v1 解析 → DoclingDocument 元素及 provenance → 需求分析 Agent → 引用回链原文件`

- TXT、Markdown、JSON、XML 仍只做确定性的段落编号，不调用 OCR。
- PDF、DOCX、PPTX、XLSX/ODS/CSV、ODT、HTML、PNG/JPEG/WEBP/TIFF/BMP 必须通过 Docling。
- 旧版 DOC/PPT/XLS/RTF 暂不进入上传白名单；待 LibreOffice 依赖完成真实验收后才能开放，不能只依据格式清单宣称支持。
- Docling 返回 `partial_success`、`skipped`、`failure`、空内容、非 v1 契约或服务不可达时立即失败。
- 不把原文件再次直接发送给模型，不保留 OpenAI 文件解析、Office 受限解析或其他本地解析 fallback。
- Docling 输出只在本次分析上下文中使用；正式业务持久化继续保存原文件、哈希、分析结果和引用，不复制 Docling 平台能力。

## 当前实现

- 新增 Docling Serve v1 客户端，启用 OCR 和准确表格模式，并读取 Markdown 与 DoclingDocument JSON。默认不发送 `ocr_lang`，使用已验收的 PP-OCRv6 中文默认模型；环境变量仅用于显式配置已验证的其他语言。
- 将 Docling 的正文、表格、图片说明、阅读顺序和 provenance 转为带来源 ID、元素引用、页码/段落号的模型上下文。
- 需求分析调用前强制完成解析；复杂文件未解析时拒绝进入模型。
- 页面新增统一解析说明，并补充 XLSX/ODS/CSV/TIFF/BMP 上传格式。
- 单元测试覆盖 v1 请求、表格恢复、页码 provenance、无原始字节直传和 partial result 停止。

## 验收状态

DI01 已于 2026-10-06 完成真实服务验收。运行环境为 Python 3.12.10、Docling Serve 1.33.0、Docling 2.133.0、DoclingDocument 1.10.0、RapidOCR/PP-OCRv6 + ONNX Runtime 1.30.0；服务监听 `127.0.0.1:5001`，模型与虚拟环境均位于 `F:\TestMesh\data`。全局 Python 3.6 已卸载，`python`、`python3`、`py` 均指向 3.12.10。

| 样本 | 真实结果 | 服务端耗时 |
| --- | --- | ---: |
| 中文扫描图片 PNG | 正文、角色表格、页码 provenance 均提取，`success` | 5.50 s |
| 中文扫描 PDF | 正文、表格、页码 provenance 均提取，`success` | 5.83 s |
| 含表格与图片 DOCX | 正文、表格、图片元素均提取，`success` | 0.14 s |
| 含图片 PPTX | 正文、图片元素和第 1 页 provenance 均提取，`success` | 0.06 s |
| 含合并单元格 XLSX | 标题、需求矩阵表格和第 1 页 provenance 均提取，`success` | 0.03 s |

TestMesh 自身适配器随后对真实 XLSX 再次调用服务，得到 `parser=docling`、DoclingDocument 1.10.0、`text/table` 两类元素，并核对到“必须保留原文引用”。54 项测试、lint、类型检查和 production build 作为最终自动验收重新执行。

LibreOffice 26.8.0.3 安装包已通过 winget 下载，但 Windows Installer 返回 1618（另一个安装事务占用），当前会话也无权重启该服务；因此没有把旧版 DOC/PPT/XLS 纳入白名单，也不把该依赖记为已安装。此限制不影响本阶段已验收的 DOCX/PPTX/XLSX 主路径。
