## 选型与职责

采用已锁定依赖的 Deep Agents 1.13.5，直接调用官方 `createDeepAgent`。此前项目只拼装 LangChain Agent 与 Deep Agents 的几个中间件，外围仍有自研框架，因此不能仅以“用了 LangGraph”声称复用了完整 Harness。

Deep Agents 提供完整 Agent Harness；LangChain 是其底层 Agent 能力，LangGraph 是其持久化执行引擎。继续使用同一官方技术栈，避免重写业务存储和多模态来源读取。单独继续使用 LangGraph 原语拼接通用治理层不能解决本次问题。

| 职责 | 迁移后的唯一实现 |
| --- | --- |
| Agent 执行与内建中间件装配 | Deep Agents `createDeepAgent` |
| 工具暴露、禁用通用子 Agent | 官方 `registerHarnessProfile` |
| 技能渐进加载 | 官方 `skills` 参数与 Skills middleware |
| 技能文件读取与临时工具结果 | 官方 CompositeBackend / FilesystemBackend / StateBackend |
| 路径权限 | 官方 `permissions`，只允许选定技能的读取 |
| 结构化模型输出 | 官方 `responseFormat` / providerStrategy |
| 需求证据检查 | 官方 `afterAgent` 扩展点内调用既有领域校验 |
| 人工评审暂停、恢复与错误状态 | LangGraph Functional API `entrypoint/interrupt/Command` |
| 持久化与运行状态查询 | 官方 PostgresSaver、`getState` / checkpoint APIs |
| 原报告、原文、评审决策和不可覆盖基线 | 原 PostgreSQL 业务表，保持业务语义 |

- https://docs.langchain.com/oss/javascript/deepagents/profiles

本阶段不开放写入/删除/Shell/子 Agent/Interpreter/RAG。禁用自动摘要以保留完整需求材料；临时工具结果使用官方 StateBackend，不写进代码目录。原模型配置和零重试保持不变。

## 删除与保留

删除整个 `server/harness` 的代码：StageProfile/TaskManifest/ArtifactEnvelope 协议、assembler、通用 completion、Foundation 探针图、stage-agent 包装、RunStore、自研 Trace 存储。删除旧需求分析 runtime、workflow 状态图和 completion-gate 封装。

六项需求分析技能移动到业务模块；来源读取、需求 Schema、证据校验、人工评审和基线存储保留。新 `service.ts` 仅连接 HTTP 与业务存储，`review.ts` 只声明业务评审步骤，不另建循环、调度、状态引擎或运行表。

删除仅测试旧框架内部协议的测试；保留并迁移证据校验测试，新增官方权限、技能、评审恢复和数据迁移测试。构建先清理服务端产物，再复制运行必需的 Skill 文件，防止旧 Harness 编译产物残留。

## 数据切换

新检查点默认使用 `deepagents_checkpoint`；不读取旧运行记录。一次性离线命令 `npm run migrate:deepagents`：

1. 校验业务库存在，拒绝在错误连接上静默创建空数据。
2. 根据既有分析和真实基线，在官方入口建立评审恢复点；未批准报告保持暂停，已有基线恢复完成。
3. 成功后删除旧 `harness_checkpoint` 和 `harness_runtime`。业务表不改写；旧失败运行的内部历史不迁移。
4. 支持重复执行，失败则停止；不提供旧 Harness 兼容读取或双写。

迁移期间必须停止旧服务。用户确认家里只 clone 了代码，没有旧数据库，因此本机创建新库；原电脑有数据时才需要执行数据切换。
