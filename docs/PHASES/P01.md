# P01：统一工作台与 PRD 多模态需求分析

- **状态**：需求分析与人工评审链路进行中（真实分析和主要页面入口已验证；用户评审与基线尚未执行）
- **目标**：在统一中文工作台交付固定协议、多模态证据可查看的需求分析闭环。

## 范围

- Refine + Ant Design 企业后台式 Shell。
- AI Chat 薄 UI，支持文本、图片和文件上传。
- Chat Attachment 与 Project Knowledge 两类入口及最小文件清单。
- 服务端直连 OpenAI Responses API。
- 固定十字段 RequirementAnalysis JSON，空类别保持空，不在需求分析里生成测试风险或用例。
- 公共 `origin` 只描述结论来自原文还是 AI 推导；待确认问题使用独立 `issue_type` 描述缺失、歧义或冲突。
- 原文引用关联来源文件，并在可靠时提供页码、段落或图片定位。
- 同一 JSON 渲染页面需求分析报告并导出 Markdown。
- 人工评审独立记录接受、驳回、合并、待澄清，保存证据核对、缺失/歧义/冲突判定及正式评审决策；待评审清单和已接受报告从同一结构化数据与评审记录导出。
- 获批 PRD 及已接受分析形成不可覆盖的需求基线；新 PRD 重新分析并关联前一基线。原始上传文件、分析 JSON、评审事件和基线均在 SQLite 持久化。
- 多文件默认无来源优先级；明确的来源优先规则作为有原文引用的业务规则，冲突保留双方证据并交人工决策。

## 验收标准

1. 用户进入统一中文工作台并打开 AI Chat。
2. 用户上传 PRD，可附带图片或截图。
3. 用户输入“帮我分析这个需求”。
4. OpenAI 多模态模型完成分析。
5. 模型输出通过固定 Schema 和来源引用校验，缺失栏目不编造内容。
6. 工作台展示中文需求分析报告，原文引用可查看；无法可靠定位时显式显示限制。
7. Markdown 导出和机器接口都读取同一已保存 JSON。
8. lint、测试和 production build 全部通过，并完成一次受控真实 API 与页面验收。
9. 原始来源可查看；人工评审按条目保留历史，不修改 AI 原始分析；驳回/合并内容不会进入已接受导出。
10. 待确认问题完成正式决策并上传获批 PRD 后才建立基线；旧基线及 PRD 文件保持可读取，新版本关联前一基线。

## 明确不做

- UI 自动化、API 测试执行、APP、性能、安全测试。
- OpenHands、Open WebUI、Langflow、Temporal、Keploy。
- Playwright、Appium、k6、ZAP。
- 向量库、复杂知识库、长流程编排、后台任务。
- 自动重试、模型切换、mock 分析或任何 silent fallback。
- 无权限的飞书接入；当前不自研文档同步、自动审批、PRD 内容语义比对或版本差异识别。
