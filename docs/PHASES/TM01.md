## 决策

TestMesh 的测试主线调整为：

`Quality Plan → Requirement Baseline → Approved Test Model → Approved TestCase → Automation/TestRun → Evaluation/Triage → Quality Report/Release Gate`

测试建模不是 Agent 内部不可见的临时推理。它是独立、可修正、可批准、不可覆盖的质量资产。没有 Approved Test Model 时，TestCase 生成接口和页面按钮均保持阻断。

## Test Model 内容

- 质量模型：目标、风险引用、覆盖目标。
- 业务模型：角色、业务规则、流程、状态、约束和异常，全部来自获批基线并保留原文引用。
- AI 模型：是否适用、TestMesh/被测 AI 双对象、Agent 决策/工具执行/业务结果/最终回复四层证据、适用 AI 维度。
- 测试分析模型：Risk、TestPoint、TestCondition、成熟工具适用性、覆盖排除和参数提取适用性。
- 知识证据：只冻结实际检索命中的项目知识片段。

## 人工与版本规则

1. Agent 只生成候选 Test Model，不生成 TestCase。
2. 人工修正必须记录修正人、理由、修改前后内容，并重新执行来源、覆盖和模型一致性校验。
3. 批准后生成不可覆盖的 Approved Test Model 版本。
4. TestCase Agent 只能读取 Approved Test Model 快照，不得重新规划或绕过模型。
5. Approved TestCase 必须记录其来源 Approved Test Model Version。
6. 质量计划和 OPA 发布准入增加 Approved Test Model 资产门禁。

## 数据清理

用户明确授权不保留存量测试设计数据。已定向清理旧 TestDesign、TestCase 评审/修正、Approved TestCase、AI Dataset/Experiment 映射、API YAML 演示运行和失败诊断；需求基线、项目配置和质量计划保留。旧版用例不提供兼容生成路径。
