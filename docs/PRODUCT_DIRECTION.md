# TestMesh 产品方向

## 北极星

TestMesh 是 **Agent / AI 应用质量保障平台**，不是需求工程工具箱，也不是把成熟工具逐个做成页面的集成目录。

平台回答四个核心问题：

1. 这个 Agent / AI 应用应该做到什么？
2. 用哪些真实样本和指标判断它做得好不好？
3. 本次运行发生了什么，失败证据在哪里？
4. 新版本是否退化，能否通过发布准入？

## 唯一质量闭环

```text
质量目标与真实需求
  → 评估集 / 测试资产
  → 在成熟 Harness 中执行目标 Agent
  → 采集输入、输出、工具调用、Trace 与业务结果
  → 成熟 Evaluator / 测试引擎评分
  → 人工复核
  → 回归比较与发布准入
```

## 需求分析的边界

项目只有一个“AI 需求分析”入口。它只负责：

- 解析 PRD、Office、PDF、表格和图片；
- 找出缺失、歧义、冲突及不可验证内容；
- 给出准确原文引用；
- 支持人工确认并形成后续质量资产的可靠输入。

Docling 等成熟组件在后台工作，不单独成为业务模块。TLA+、DMN、FRET 等候选只有在具体 Agent 质量场景证明必要、且能被平台自动调用时才重新评审；不要求普通用户手写专业模型。

## Reuse-first 判定顺序

每增加一项能力都按以下顺序决策：

1. 先定义要解决的 Agent / AI 应用质量问题和可验收结果。
2. 调研成熟标准、开源项目和商业产品，不受推荐表限制。
3. 选择一条最小、可私有部署或满足企业数据边界的路径。
4. TestMesh 只实现成熟组件没有提供的业务映射、统一入口和证据关联。
5. 没有真实样本端到端验收，不进入产品导航和正式路线。

## TestMesh 应保留的能力

- 目标 Agent / AI 应用、版本和环境标识。
- requirement、dataset、case、run、trace、evaluation、artifact 的业务关联。
- 企业质量目标、评估配置、风险容忍度和准入策略。
- 跨工具统一入口、运行证据、历史比较与人工复核。

## TestMesh 不应自研的能力

- Agent Loop、Workflow Runtime、Checkpoint、Tool Executor。
- OCR、文档版面、浏览器/API/安全/性能 Runner。
- Trace 存储与通用 Eval 实验平台。
- 通用规则语言、模型检查器、测试管理系统或报告引擎。
- 已有成熟实现的生成器、组合覆盖、状态路径和测试结果格式。

## 当前纠偏

2026-10-08，用户确认推荐表只是候选清单，终极目标是 Agent / AI 应用质量保障。独立“形式化验证”和“业务规则”路径被撤回并删除；其调研结论仅作历史证据，不代表产品能力或后续承诺。
