# 场景设计

- 使用 `功能 → 规则 → 场景/场景大纲` 表达业务可观察行为。
- 每个场景说明初始上下文（假如）、业务事件（当）和可验证结果（那么）。
- 规则分支使用独立场景；同一逻辑的多组明确数据使用场景大纲和 `例子:` 表。`示例:` 不是 Cucumber zh-CN 的合法关键字，禁止使用。
- 避免 UI 点击细节、实现术语和无法观察的“处理正确”。
- 使用标签保存 TestCase 和基线条目 ID。
- Gherkin 文档内不追加解释性段落、Markdown 或项目符号；补充说明放在结构化用例字段。必须保留说明时只能使用以 `#` 开头的 Gherkin 注释。
